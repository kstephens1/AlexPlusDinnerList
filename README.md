# Dinnertime Alexa Widget

Dinnertime is an Alexa custom skill plus APL widget for Echo Show devices. The widget is intended to be added to the home screen / widget panel and display read-only dinner menu records from Alexa Data Store.

## Deployment Profile

- Skill name: `Dinnertime`
- Invocation name: `dinnertime`
- Skill ID: set locally in `.env` as `ALEXA_SKILL_ID`
- Lambda: generated by `scripts/deploy.sh`
- AWS profile: set locally in `.env` as `AWS_PROFILE`
- ASK profile: set locally in `.env` as `ASK_PROFILE`
- Region: set locally in `.env` as `AWS_REGION`
- Locales: `en-US`, `en-GB`

Test phrase:

```text
open dinnertime
```

## Architecture

- `skill-package/skill.json` defines the Alexa skill manifest and enabled interfaces.
- `skill-package/interactionModels/custom/en-US.json` defines the voice model.
- `skill-package/dataStorePackages/DinnertimeWidget` contains the APL widget package.
- `lambda/index.js` handles launch requests and widget/Data Store lifecycle events.
- S3 stores the editable dinner menu JSON and the lightweight Alexa target registry.
- `scripts/deploy.sh` deploys Lambda and skill metadata.

The widget uses Amazon's recommended pattern for dynamic widget content:

1. The widget package ships a fallback datasource.
2. The widget binds to Alexa Data Store on-device data.
3. External systems update the S3 menu JSON.
4. S3 object-created events trigger Lambda.
5. Lambda writes the new menu array into Alexa Data Store for registered widget targets.

The Lambda also seeds Alexa Data Store when the widget install/open lifecycle arrives, using the current S3 menu if available and falling back to the bundled five records if S3 is unavailable.

## Data Store Contract

The widget reads live menu state from:

```text
namespace: Dinnertime
key: state
```

Expected value:

```json
{
  "title": "Dinnertime",
  "items": [
    {
      "date": "2026-04-28",
      "day": "Tue",
      "text": "meal 1"
    }
  ],
  "lastUpdated": "2026-05-13",
  "latestMealDate": "2026-04-28"
}
```

Rules:

- `date` is a `YYYY-MM-DD` string.
- `day` is added by Lambda before writing to Alexa Data Store.
- `text` is the meal text.
- `text` max length is 500 characters.
- Lambda currently syncs up to 50 records from the S3 source.
- The widget list scrolls vertically and rows expand to show full meal text.

Schema reference:

```text
docs/schemas/dinner-menu-items.schema.json
```

The Data Store namespace is still `DinnerList` intentionally. The skill was renamed to `Dinnertime`, but keeping the namespace stable avoids breaking existing simulator/device data.

## Fallback Data

If Alexa Data Store has no live data for `DinnerList/items`, the widget falls back to:

```text
meal 1
meal 2
meal 3
meal 4
meal 5
```

Defined in:

```text
skill-package/dataStorePackages/DinnertimeWidget/datasources/default.json
```

If the simulator shows different meal text, that data is coming from the simulator's Data Store state, not the fallback file.

On a physical device, if the widget title renders but the list is blank, remove and re-add the widget after deploying the Lambda so the `UsagesInstalled` lifecycle event fires again. That event causes Lambda to write the fallback records into the device's Alexa Data Store.

## Deployment

Credentials already used successfully:

- AWS CLI profile `default`
- ASK CLI profile `default`

Deploy everything:

```bash
./scripts/deploy.sh
```

The script:

- validates Lambda syntax
- packages Lambda
- creates or updates the Lambda execution role
- creates or updates the Lambda function
- writes the Lambda ARN into `skill-package/skill.json`
- ensures the Alexa skill can invoke Lambda
- deploys skill metadata with ASK CLI when `DEPLOY_SKILL=1`

Important local config:

```text
.env
```

Current expected values:

```bash
AWS_REGION=us-east-1
AWS_PROFILE=default
LAMBDA_FUNCTION_NAME=alexa-plus-dinner-list
ALEXA_SKILL_ID=amzn1.ask.skill.xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
DEPLOY_SKILL=1
ASK_PROFILE=default
MENU_KEY=dinner-menu/items.json
TARGETS_KEY=dinner-menu/targets.json
```

If `S3_BUCKET_NAME` is empty, `scripts/deploy.sh` creates/uses:

```text
alexa-plus-dinner-list-<aws-account-id>-us-east-1
```

Live menu source:

```text
s3://<bucket>/dinner-menu/items.json
```

Expected file body:

```json
[
  {
    "date": "2026-05-13",
    "text": "Chicken curry"
  }
]
```

When this object is updated, S3 invokes Lambda and Lambda pushes the new array into Alexa Data Store for devices/users that have opened or installed the widget.

More detailed deployment instructions are in:

```text
DEPLOYMENT.md
```

## Alexa Developer Console Testing

1. Open the Alexa Developer Console.
2. Open the `Dinnertime` skill.
3. Go to **Test**.
4. Make sure testing is enabled for the development stage.
5. Type or say:

   ```text
   open dinnertime
   ```

Use the same locale in the simulator as the skill model. This project supports `en-US` and `en-GB`. If the simulator/device locale has no matching interaction model, Alexa may route the phrase to the built-in Lists feature instead.

## Notes

- The Lambda function name still contains `dinner-list`; it was not renamed to avoid replacing the deployed function.
- The current widget package ID is `DinnertimeWidget`. The original development package ID was `DinnerListWidget`; it was replaced to avoid stale development-stage widget installs.
- The widget icon and preview URLs are placeholders and should be replaced before certification.
